# Week 3 - Password Cracking with PDF Files

**Cybersecurity & Ethical Hacking Internship - Networkwalks**

This week's tasks focused on recovering the password of a protected PDF file (`My Locked PDF1.pdf`) using two different approaches:

- **Project Module 1** - Extracting the hash with OnlineHashCrack and cracking it using **JTR (John the Ripper) / Johnny GUI**
- **Project Module 2** - Extracting and cracking the hash entirely with **Networkwalks' own online tools** (Hash Calculator + Password Cracker)

Both exercises demonstrate the same underlying concept: a password-protected file stores its password as a hash rather than plain text, and a cracking tool recovers the original password by testing candidate words against that hash until it finds a match.

---

## Project Module 1 - Cracking with JTR / Johnny

**Goal:** Crack the password of `My Locked PDF1.pdf` using John the Ripper's GUI front-end, Johnny.

### Step 1 - Extract the hash from the PDF

Used the OnlineHashCrack PDF Hash Extractor tool to pull a crackable hash (`pdf2john` / hashcat-compatible format) out of the locked PDF:

🔗 https://www.onlinehashcrack.com/tools-pdf-hash-extractor.php

Uploaded `My Locked PDF1.pdf`, and the tool returned the hash starting with `$pdf$...`.

`![Hash extracted from OnlineHashCrack](screenshots/pm1-hash-extractor.png)`

### Step 2 - Save the hash to a text file

Copied the full hash value and saved it as `hash.txt`, making sure the hash started cleanly with `$pdf$` (removing any stray characters such as a leading `b'` that can sometimes get pasted in).

```
$pdf$4*4*128*-1028*1*16*ca7f72f11459cba469f1005a8765ed51*32*f32d8fa1bfbe2648226dffc39f7909ea0021446990b9e4114071a4d9104984c1*32*9322f50c29569712067a775264635e4954ccb1b99e209d664984054ffad30a6a
```

### Step 3 - Load the hash into Johnny

Opened **Johnny** (the graphical front-end for John the Ripper), clicked **Open password file**, and pointed it to `hash.txt`.

### Step 4 - Run the attack

Clicked **Start new attack** and let Johnny work through its wordlist against the hash.

### Step 5 - Result

Johnny cracked the hash successfully:

**Recovered password:** `good-luck`

`![Johnny GUI showing the cracked password](screenshots/pm1-johnny-cracked.png)`

### Step 6 - Verify

Opened `My Locked PDF1.pdf`, entered `good-luck` as the document password, and confirmed the file unlocked successfully.

## Project Module 2 - Cracking with Networkwalks Tools

**Goal:** Repeat the same task end-to-end using Networkwalks' own browser-based tools instead of JTR.

### Step 1 - Extract the hash with the Hash Calculator

🔗 https://networkwalks.com/hash-calculator/

Uploaded `My Locked PDF1.pdf` under the **PDF** tab. The tool parsed the file locally in the browser and returned the same style of crackable hash (`$pdf$...`).

`![Hash generated by Networkwalks Hash Calculator](screenshots/pm2-hash-calculator.png)`

### Step 2 - First attempt with the built-in wordlist

🔗 https://networkwalks.com/password-cracker/

Pasted the hash into the Password Cracker and ran the attack using its **built-in list (100 passwords)**.

**Result:** ❌ Access denied - the built-in wordlist was too small and didn't contain the correct password.

`![Access denied with the built-in wordlist](screenshots/pm2-access-denied.png)`

### Step 3 - Retry with a larger wordlist (rockyou.txt)

Uploaded `rockyou.txt` - a much larger, well-known password dictionary - as a custom wordlist and re-ran the attack.

### Step 4 - Result

The larger wordlist succeeded where the built-in list failed, confirming the hash and recovering the password.

`![PDF successfully unlocked with the cracked password](screenshots/pm2-pdf-unlocked.png)`

## Key Takeaways

- A locked PDF doesn't store its password directly - it stores a **hash**, which must be extracted before it can be cracked.
- Both JTR/Johnny and Networkwalks' tools follow the same two-stage process: **extract the hash → run a dictionary attack against it**.
- **Wordlist size matters.** A small, generic wordlist (100 passwords) failed completely, while `rockyou.txt` - containing millions of real-world leaked passwords - succeeded. This is a practical illustration of why weak or common passwords are so easily compromised in the real world.
- This lab reinforces why organizations enforce strong, unique passwords: short or dictionary-based passwords can be cracked in minutes with freely available tools.
